These are **plans, not promises** — nothing below is shipped in v0.15.0.

- ~~**Real e-signature**~~ — shipped in v0.3.0: typed-name / drawn-signature capture on the contract, stored with the project, SHA-256 tamper evidence.
- ~~**Late-fee accrual calculator**~~ — shipped in v0.4.0: monthly-compounding accrual of contract §3 fees, `invoice late-fees` CLI, dashboard rows, dunning template variables.
- ~~**SMS / WhatsApp escalation**~~ — shipped in v0.5.0: day-15 also goes out as an SMS/WhatsApp message via Twilio when configured, plus `invoice notify` for one-off reminders.
- **Agency mode** — multi-freelancer workspaces (unshipped); per-client dunning policies shipped in v0.7.0 (`invoiceguard client set-dunning-policy`); freelancer roster + invoice attribution shipped in v0.8.0 (`invoiceguard freelancer add`, `invoiceguard invoice assign`); freelancer earnings shipped in v0.9.0 (`invoiceguard freelancer show`, per-currency billed/collected/outstanding); freelancer payouts shipped in v0.10.0 (`invoiceguard payout record` / `payout list`, per-currency payout ledger with an over-payout guard); revenue splits shipped in v0.11.0 (`freelancer add --split-pct` / `freelancer set-split`, per-currency expected share + still-due-to-freelancer); payout suggestions shipped in v0.12.0 (`invoiceguard payout suggest`, per-currency still-due share or still-held balance when no split is set); payout settlement shipped in v0.13.0 (`invoiceguard payout settle`, records every suggestion at once through the payout guard, no-split freelancers skipped, `--dry-run` writes nothing). agency summary shipped in v0.14.0 (`invoiceguard agency summary`, whole-book view per freelancer per currency with per-currency totals, read-only); payout schedules shipped in v0.15.0 (`freelancer set-schedule` / `clear-schedule`, `invoiceguard payout schedule` with derived next payout date, read-only); payouts due shipped in v0.16.0 (`invoiceguard payout due`, scheduled freelancers with an actionable payout on/inside the pay-run window, read-only); settle the pay run shipped in v0.17.0 (`invoiceguard payout settle-due`, one payout per due row through the payout guard, no-split freelancers skipped, `--dry-run` writes nothing, second run is a no-op); payouts overdue shipped in v0.18.0 (`invoiceguard payout overdue`, scheduled freelancers whose most recent payout date passed with an actionable payout and nothing recorded since that date, read-only); settle the missed pay runs shipped in v0.19.0 (`invoiceguard payout settle-overdue`, one payout per overdue row through the payout guard, no-split freelancers skipped, `--dry-run` writes nothing, second run is a no-op); payout timing on the agency summary shipped in v0.20.0 (`invoiceguard agency summary [--as-of DATE]`, per-currency due/overdue/upcoming/settled/no-schedule status with next or missed payout date, derived from the `payout due`/`overdue` rules, read-only); payout timing on the agency summary TOTALS shipped in v0.21.0 (`reports.agency_summary_totals()`, per-currency rollup of the rows' own statuses — overdue beats due beats upcoming, with freelancer count and earliest missed/next date; a settled/no-schedule mix carries no status rather than a misleading one, read-only); payout timing on `freelancer show` shipped in v0.22.0 (`invoiceguard freelancer show ID [--as-of DATE]`, per-currency due/overdue/upcoming/settled/no-schedule status with next or missed payout date, taken from the same `agency summary` rows, read-only); payout timing on `payout suggest` shipped in v0.23.0 (`invoiceguard payout suggest [--as-of DATE]`, per-suggestion due/overdue/upcoming/no-schedule status with next or missed payout date, derived from the `payout due`/`overdue` rules, read-only); payout timing on `payout schedule` shipped in v0.24.0 (`invoiceguard payout schedule [--as-of DATE]`, per-freelancer due/overdue/upcoming/settled/no-schedule status rolled up across currencies with the same overdue-beats-due-beats-upcoming precedence, read-only). payout timing on `freelancer list` shipped in v0.25.0 (`invoiceguard freelancer list [--as-of DATE]`, the same per-freelancer rollup appended to each roster line, read-only); payout timing on `invoice report` shipped in v0.26.0 (`invoiceguard invoice report [--as-of DATE]`, per-currency due/overdue/upcoming/settled/no-schedule status on each 'by freelancer' line, taken from the same `agency summary` rows, read-only). payout timing on `payout list` shipped in v0.27.0 (`invoiceguard payout list [--as-of DATE]`, the same per-freelancer rollup on each freelancer's newest payout row, read-only). payout timing on the web dashboard shipped in v0.28.0 (dashboard index Payouts section, the same per-freelancer rollup as of today, read-only). payout timing on the invoice detail page shipped in v0.29.0 (dashboard `GET /invoices/{id}`, the same per-freelancer rollup on the Freelancer row as of today, read-only). dashboard payout timing as-of projection shipped in v0.30.0 (`GET /?as_of=YYYY-MM-DD` and `GET /invoices/{id}?as_of=YYYY-MM-DD`, the same per-freelancer rollup projected to that day, invalid date is a clean 400, filter/Details/back links keep the projection, read-only). payout timing in the `invoice report` CSV export shipped in v0.31.0 (`invoiceguard invoice report [--csv PATH]`, trailing `payout_status` / `payout_date` columns per row from the same `agency summary` rows, projected with `--as-of`, unassigned rows carry empty cells, read-only). payout timing in the `invoice report` payments CSV export shipped in v0.32.0 (`invoiceguard invoice report [--payments-csv PATH]`, trailing `payout_status` / `payout_date` columns per payment row, joined through the payment's invoice attribution and currency, projected with `--as-of`, unassigned rows carry empty cells, payments on paid invoices still export with timing, read-only). CSV export for `agency summary` shipped in v0.33.0 (`invoiceguard agency summary [--csv PATH]`, one row per freelancer per currency plus one TOTALS row per currency, with the same money columns and the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, read-only). CSV export for `payout list` shipped in v0.34.0 (`invoiceguard payout list [--csv PATH]`, one row per recorded payout, newest first, with the same payout timing in trailing `payout_status` / `payout_date` columns on the newest row per freelancer, projected with `--as-of`, `-` prints to stdout, empty ledger exports a header-only CSV, read-only). CSV export for the pay-run lists shipped in v0.35.0 (`invoiceguard payout due [--csv PATH]` and `invoiceguard payout overdue [--csv PATH]`, one row per pay-run row with the same columns the text lists print — freelancer, currency, still-due share or still-held balance, schedule, next payout date, plus the missed payout date on overdue rows — projected with `--as-of` (and `--within-days` for `due`), `-` prints to stdout, empty pay run exports a header-only CSV, read-only). CSV export for `payout suggest` shipped in v0.36.0 (`invoiceguard payout suggest [--csv PATH]`, one row per suggestion per currency with the same columns the text lines print — freelancer, currency, still-due share or still-held balance, collected, paid out, split — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, empty suggestion list exports a header-only CSV, read-only). CSV export for `payout schedule` shipped in v0.37.0 (`invoiceguard payout schedule [--csv PATH]`, one row per roster freelancer with the same columns the text lines print — freelancer, schedule cadence and day, next payout date — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, empty roster exports a header-only CSV, read-only). CSV export for `freelancer list` shipped in v0.38.0 (`invoiceguard freelancer list [--csv PATH]`, one row per roster freelancer with the same columns the text lines print — freelancer, email, phone, split — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, empty roster exports a header-only CSV, read-only). CSV export for `freelancer show` shipped in v0.39.0 (`invoiceguard freelancer show ID [--csv PATH]`, one row per currency earnings line with the same contact, schedule, and money columns the text view prints — including the split-derived expected share and still-due-to-freelancer columns, which no earlier export carried — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, the attributed invoice lines and the recorded payouts stay text-only, read-only). CSV export for the attributed invoice lines of `freelancer show` shipped in v0.40.0 (`invoiceguard freelancer show ID [--invoices-csv PATH]`, one row per attributed invoice in the same id order the text lines print them, with the same columns the text lines print — invoice id, client, currency, amount, collected, outstanding, status — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, drafts and voids excluded, no attributed invoices exports a header-only CSV, the recorded payouts stay text-only, read-only). CSV export for the recorded payouts of `freelancer show` shipped in v0.41.1 (`invoiceguard freelancer show ID [--payouts-csv PATH]`, one row per recorded payout in the same newest-first order the text lines print them, with the same columns the text lines print — payout id, currency, amount, paid date, method, note — plus the same timing in trailing `payout_status` / `payout_date` columns, projected with `--as-of`, `-` prints to stdout, no recorded payouts exports a header-only CSV, the whole `freelancer show` screen is now a spreadsheet, read-only). CSV export for `invoice list` shipped in v0.42.0 (`invoiceguard invoice list [--csv PATH]`, one row per listed invoice in the same id order the text lines print them, with the same columns the text lines print — invoice id, kind, status, amount, currency, project, freelancer, due date — freelancer empty when unassigned and due date empty when unset, `--freelancer ID` composes with the export, `-` prints to stdout, empty list exports a header-only CSV, no payout timing columns since the list carries no `--as-of`, read-only). CSV export for `client list` and `project list` shipped in v0.43.0 (`invoiceguard client list [--csv PATH]` and `invoiceguard project list [--csv PATH]`, one row per client / project in the same id order the text lines print them, with the same columns the text lines print — client id, name, email, phone, plus the dunning-policy overrides per stage (`off` when disabled, empty at the global default); project id, title, client, amount, currency, contract acknowledgment (`ack` / `no-ack`) — `-` prints to stdout, empty lists export a header-only CSV, no payout timing columns since neither list carries an `--as-of`, read-only). CSV export for `invoice late-fees` shipped in v0.44.0 (`invoiceguard invoice late-fees ID [--csv PATH]`, one row for the invoice with the same columns the text view prints — invoice id, client, project, currency, due date, rate, grace days, accrual start, as-of date, outstanding, months billed, accrued fees, total due — projected with `--as-of`, `-` prints to stdout, no due date exports empty accrual cells with zero fees, read-only). payout timing on `invoice list` shipped in v0.45.0 (`invoiceguard invoice list [--as-of DATE]`, per-(freelancer, currency) due/overdue/upcoming/settled/no-schedule status on each line in the invoice's own currency, taken from the same `agency summary` rows, projected with `--as-of`, unassigned invoices carry no phrase, read-only; the CSV export gains the same timing in trailing `payout_status` / `payout_date` columns).
- ~~**Partial payments / payment plans**~~ — shipped in v0.2.0.

Priorities follow real user feedback. If a roadmap item matters to you, open an issue on [GitHub](https://github.com/Bilal-Junaid-Jiwani/invoiceguard) describing your workflow.
