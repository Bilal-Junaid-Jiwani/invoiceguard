The CLI entry point is `invoiceguard` (installed by pip). All commands below are from v0.10.0 — run `invoiceguard --help` or `invoiceguard <group> --help` for the same text locally.

## `init`

```bash
invoiceguard init
```

Creates `~/.invoiceguard/`: the config template, an empty SQLite database, and the three dunning email templates. Idempotent — existing files are left alone.

## `client`

```bash
invoiceguard client add --name "Acme Corp" --email "billing@acme.com" [--phone +15551234567]
invoiceguard client set-phone 1 [--phone +15551234567]   # omit --phone to clear
invoiceguard client set-email 1 [--email billing@acme.com]     # omit --email to clear
invoiceguard client set-dunning-policy 1 [--day1 N] [--day7 N] [--day15 N] [--reset]
invoiceguard client list [--csv PATH]   # CSV in v0.43.0
```

- `add` requires `--name`; `--email` is optional (needed later for dunning emails). `--phone` (E.164 form) enables SMS/WhatsApp escalation for that client; invalid numbers are rejected.
- `set-phone` updates or clears the phone number of an existing client.
- `set-email` updates or clears the email address of an existing client (dunning).
- `set-dunning-policy` sets per-client dunning stage thresholds (v0.7.0, agency mode): each `--dayN` is the days-overdue threshold for that stage; `0` disables the stage for that client; omit a flag to leave it unchanged. Thresholds must stay in escalation order (day1 → day7 → day15); negative values are rejected. `--reset` clears overrides back to the global defaults (1/7/15).
- `list` prints `#id  name  email  phone` rows, plus a `[dunning ...]` marker for clients with policy overrides. `--csv PATH` (v0.43.0) exports the same list as a spreadsheet: one row per client with the same columns the text lines print plus the dunning-policy overrides per stage (`off` when disabled, empty at the global default). `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. CSV exports neutralize spreadsheet formula injection (see `report`).

## `freelancer` (v0.8.0, agency mode)

```bash
invoiceguard freelancer add --name "Ali R." [--email ali@example.com] [--phone +15551234567] [--split-pct 70]
invoiceguard freelancer set-email 1 [--email ali@example.com]   # omit --email to clear
invoiceguard freelancer set-phone 1 [--phone +15551234567]     # omit --phone to clear
invoiceguard freelancer set-split 1 --split-pct 70   # v0.11.0
invoiceguard freelancer list [--as-of 2026-10-28] [--csv PATH]   # timing in v0.25.0, CSV in v0.38.0
invoiceguard freelancer show 1 [--as-of 2026-10-28] [--csv PATH] [--invoices-csv PATH] [--payouts-csv PATH]   # v0.9.0, CSV in v0.39.0, invoices CSV in v0.40.0, payouts CSV in v0.41.1
```

- The agency roster: one row per team member. `add` requires `--name`; `--phone` must be E.164 (invalid numbers are rejected).
- `list` prints `#id  name  email  phone` rows. Each line also carries payout timing (v0.25.0): due, overdue (with the missed run date), upcoming, settled, or no schedule — the most urgent status across the freelancer's currencies, taken from the same `payout_schedule_timing()` rollup `payout schedule` uses, derived from the exact `payout due`/`overdue` rules as of `--as-of` (default: today); an invalid date is a clean error, and freelancers with no billable invoices carry no timing phrase. `--csv PATH` (v0.38.0) exports the same roster as a spreadsheet: one row per freelancer, in the same order the text list prints them, with the same columns the text lines print (freelancer, email, phone, split) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule. No-split rows carry an empty `split_pct` cell; freelancers with no billable invoices carry empty timing cells. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty roster exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only.
- `show` (v0.9.0; payouts added in v0.10.0, revenue splits in v0.11.0, payout schedule line in v0.15.0, payout timing in v0.22.0) prints contact details, per-currency earnings — billed (attributed invoices in a real state; drafts and voids excluded), collected (payment-ledger sums), outstanding — plus paid out and still owed from the payout ledger, the attributed invoice lines with collected/outstanding per invoice, and the recorded payouts. When a revenue split is set it also prints the freelancer's expected share of each collected currency and what is still due to them after payouts. When a payout schedule is set it prints the schedule and the derived next payout date. Each currency line also carries payout timing (v0.22.0): due, overdue (with the missed run date), upcoming, settled, or no schedule — taken from the same `agency summary` rows, derived from the exact `payout due`/`overdue` rules as of `--as-of` (default today); an invalid date is a clean error, and freelancers with no billable invoices carry no timing phrase. `--csv PATH` (v0.39.0) exports the earnings detail as a spreadsheet: one row per currency earnings line, in the same order the text view prints them, with the same columns the text lines print (freelancer, email, phone, split, schedule cadence and day, currency, billed, collected, outstanding, invoice count, paid out, still owed, expected share, still due to the freelancer) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule. No-split rows carry empty share cells; a freelancer with no billable invoices gets one row with an empty currency and empty share and timing cells. `-` prints the CSV to stdout instead of the text view; a file path writes the file and still prints the text view. `--invoices-csv PATH` (v0.40.0) exports the attributed invoice lines as a spreadsheet: one row per attributed invoice, in the same id order the text lines print them, with the same columns the text lines print (invoice id, client, currency, amount, collected, outstanding, status) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule. Drafts and voids stay excluded; a freelancer with no attributed invoices exports a header-only CSV. `-` prints the CSV to stdout instead of the text view; a file path writes the file and still prints the text view. `--payouts-csv PATH` (v0.41.1) exports the recorded payouts as a spreadsheet: one row per payout, in the same newest-first order the text lines print them, with the same columns the text lines print (payout id, currency, amount, paid date, method, note) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule. A freelancer with no recorded payouts exports a header-only CSV. `-` prints the CSV to stdout instead of the text view; a file path writes the file and still prints the text view. `--csv`, `--invoices-csv`, and `--payouts-csv` can be used together to separate files; only one may print to stdout. With all three exports the whole `freelancer show` screen is now a spreadsheet. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only.
- `--split-pct` (v0.11.0) records the freelancer's revenue-split percentage of *collected* earnings (0–100, validated before write); `freelancer set-split` changes it later. NULL (unset) means the freelancer is earnings bookkeeping only. Bookkeeping only — the split is reported, never transferred, and the payout guard is unchanged.
- `set-schedule` (v0.15.0) records a recurring payout schedule: `--cadence weekly` with `--day` 1–7 (ISO weekday, Monday–Sunday) or `--cadence monthly` with `--day` 1–31 (day of month, clamped to the month's last day when derived); `clear-schedule` clears it. Validated before write; a schedule never records or transfers a payout.
- Invoices are attributed to a freelancer with `invoice assign` (see below) — attribution is bookkeeping only and never changes dunning, payments, or invoice status.

## `payout` (v0.10.0, agency mode)

```bash
invoiceguard payout record --freelancer 1 --amount 250 [--currency USD] \
    [--paid-at 2026-10-23] [--method "bank transfer"] [--note "Sept share"]
invoiceguard payout list [--freelancer 1] [--as-of 2026-10-28] [--csv PATH]   # timing in v0.27.0, CSV in v0.34.0
invoiceguard payout suggest [--freelancer 1] [--as-of 2026-10-28] [--csv PATH]   # v0.12.0, timing in v0.23.0, CSV in v0.36.0
invoiceguard payout settle [--freelancer 1] [--currency USD] [--dry-run]   # v0.13.0
invoiceguard payout schedule [--freelancer 1] [--as-of 2026-10-28] [--csv PATH]   # v0.15.0, timing in v0.24.0, CSV in v0.37.0
invoiceguard payout due [--freelancer 1] [--as-of 2026-10-28] [--within-days 7] [--csv PATH]   # v0.16.0, CSV in v0.35.0
invoiceguard payout settle-due [--freelancer 1] [--as-of 2026-10-28] [--within-days 7] [--currency USD] [--dry-run]   # v0.17.0
invoiceguard payout overdue [--freelancer 1] [--as-of 2026-10-31] [--csv PATH]   # v0.18.0, CSV in v0.35.0
invoiceguard payout settle-overdue [--freelancer 1] [--as-of 2026-10-28] [--currency USD] [--dry-run]   # v0.19.0
```

- Records what the agency sent a freelancer — bookkeeping only, nothing is transferred. A payout is refused with a clear error when it exceeds what the agency has collected for that freelancer in that currency (payment-ledger sums against their attributed non-draft/void invoices, minus payouts already recorded); you cannot pay out money you have not received. Currency codes are normalized to upper-case; invoice-currency matching is case-insensitive; `--paid-at` accepts `YYYY-MM-DD` (default: now).
- `list` prints `#id  name  currency  amount  date  method  note` rows, newest first; `--freelancer ID` restricts to one freelancer. Each freelancer's most recent payout line also carries payout timing (v0.27.0): due, overdue (with the missed run date), upcoming, settled, or no schedule — the most urgent status across the freelancer's currencies, taken from the same `payout_schedule_timing()` rollup `payout schedule` uses, derived from the exact `payout due`/`overdue` rules as of `--as-of` (default: today); an invalid date is a clean error, and freelancers with no billable invoices carry no timing phrase. The timing appears once per freelancer, on their newest payout. `--csv PATH` (v0.34.0) exports the same ledger as a spreadsheet: one row per payout, newest first, with the same columns the text list prints (payout id, freelancer, currency, amount, paid-at, method, note) and the same timing in trailing `payout_status` / `payout_date` columns — on the newest row per freelancer only; older rows carry empty timing cells. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty ledger exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only. Revenue splits shipped in v0.11.0 (`freelancer set-split`); per-freelancer payout schedules shipped in v0.15.0 (`freelancer set-schedule`, `payout schedule`).
- `suggest` (v0.12.0) answers "what do I pay next?", per freelancer per currency, largest first. With a split set it prints the still-due share — expected share of what was collected minus payouts already recorded, floored at zero and never above what the agency still holds for them; a freelancer paid their full share, or paid past it, produces no row. Without a split it reports what the agency still holds for them, labeled as available rather than suggested, with a pointer to `freelancer set-split`. Each line also carries payout timing (v0.23.0): due, overdue (with the missed run date), upcoming, or no schedule — derived from the exact `payout due`/`overdue` rules as of `--as-of` (default: today); an invalid date is a clean error. `--csv PATH` (v0.36.0) exports the same suggestions as a spreadsheet: one row per suggestion per currency with the same columns the text lines print (freelancer id, freelancer, currency, the still-due share — empty when no split is set — the still-held balance, collected, paid out, and the split) plus the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for no schedule. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty suggestion list exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only: nothing is recorded or transferred, and `payout record` still enforces its own guard.
- `settle` (v0.13.0) records every suggestion at once, one payout per suggestion for the suggested amount, through the same guard — a fresh suggestion can never be refused. `--freelancer ID` / `--currency CUR` restrict the run; `--dry-run` prints what would be recorded and writes nothing. Freelancers with no split set are skipped with a count, never guessed at; a second settle is a no-op, so nothing is double-paid. Bookkeeping only, like `record`.
- `schedule` (v0.15.0) shows each roster freelancer's payout schedule and derived next payout date, earliest first; freelancers with no schedule set are listed as such, and an empty roster prints `no freelancers on the roster`. `--as-of DATE` projects dates as of that day (default: today). Each line also carries payout timing (v0.24.0): due, overdue (with the missed run date), upcoming, settled, or no schedule — the most urgent status across the freelancer's currencies, taken from the same `agency summary` rows, derived from the exact `payout due`/`overdue` rules as of `--as-of` (default today); an invalid date is a clean error, and freelancers with no billable invoices carry no timing phrase. `--csv PATH` (v0.37.0) exports the same schedules as a spreadsheet: one row per roster freelancer, in the same order the text list prints them, with the same columns the text lines print (freelancer, schedule cadence and day, next payout date) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule. Unscheduled rows carry empty schedule and date cells; freelancers with no billable invoices carry empty timing cells. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty roster exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only: a schedule never records or transfers a payout.
- `due` (v0.16.0) shows the pay run: scheduled freelancers whose next payout date falls on the pay-run date (default: today), or within `--within-days N` days after it, and who have an actionable payout suggestion — a still-due split share, or the still-held balance when no split is set (labeled as available). Rows sort by next payout date, earliest first, then largest amount first. Unscheduled freelancers are never due, and a due date with nothing to pay produces no row; a roster with nothing due prints `no payouts due`. Read-only: record the run with `payout settle-due`. `--csv PATH` (v0.35.0) exports the same pay run as a spreadsheet: one row per due freelancer per currency with the same columns the text list prints (freelancer id, freelancer, currency, the still-due split share — empty when no split is set — the still-held balance, the schedule's cadence and day, and the next payout date); due rows carry an empty `missed_payout_date` cell. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty pay run exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`).
- `settle-due` (v0.17.0) records the pay run `due` lists: one payout per due row, for the suggested amount, through the same guard as `payout record`. Unlike `settle`, which settles the whole book, this settles only the freelancers whose payout date has arrived — a freelancer due next week keeps their suggestion until their own pay run. `--as-of DATE` / `--within-days N` set the pay-run window (default: today only); `--freelancer ID` / `--currency CUR` restrict the run; `--dry-run` prints what would be recorded and writes nothing. Freelancers with no split set are skipped with a count, never guessed at; an empty roster prints `no freelancers on the roster`, a roster with nothing due prints `no payouts due`, and a second settle-due on the same pay run is a no-op. Bookkeeping only, like `record`.
- `overdue` (v0.18.0) shows the missed pay runs: scheduled freelancers whose most recent scheduled payout date has already passed, who still have an actionable payout — a still-due split share, or the still-held balance when no split is set (labeled as available) — and who have nothing recorded for that currency since that missed date. Rows sort by missed payout date, earliest first, then largest amount first. A freelancer due on the pay-run date itself appears in `due`, not here, and money collected since the last run waits for the next run. `--freelancer ID` restricts to one freelancer; an empty roster prints `no freelancers on the roster`, a roster with nothing overdue prints `no overdue payouts`. Read-only: record a missed run with `payout settle-overdue` (just the missed runs), `payout record` (one amount by hand), or `payout settle` (the whole book). `--csv PATH` (v0.35.0) exports the same missed runs as a spreadsheet: one row per overdue freelancer per currency with the same columns the text list prints, plus the `missed_payout_date` the text lines print. `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. An empty missed run exports a header-only CSV. CSV exports neutralize spreadsheet formula injection (see `report`).
- `settle-overdue` (v0.19.0) records the missed runs `overdue` lists: one payout per overdue row, for the suggested amount, through the same guard as `payout record`. Unlike `settle-due`, which settles only the pay run whose date has arrived, this settles only the runs already missed — a freelancer due on the pay-run date itself stays in `settle-due`, and a freelancer paid at or after the missed run is not overdue at all. `--freelancer ID` / `--currency CUR` restrict the run; `--dry-run` prints what would be recorded and writes nothing. Freelancers with no split set are skipped with a count, never guessed at; an empty roster prints `no freelancers on the roster`, a roster with nothing overdue prints `no overdue payouts`, and a second settle-overdue on the same missed runs is a no-op. Bookkeeping only, like `record`.

## `agency` (v0.14.0, agency mode)

```bash
invoiceguard agency summary [--freelancer 1] [--as-of 2026-11-15] [--csv summary.csv]
```

- The whole book at a glance: one section per roster freelancer — per-currency billed, collected, outstanding, paid out, and still owed, plus the suggested payout (the still-due split share) where one exists — followed by a `TOTALS` section summing each currency across the roster, with a suggested total where any split freelancer still has a share due. Each currency line also carries payout timing (v0.20.0): the freelancer's schedule, next payout date, and whether that currency is due, overdue, upcoming, settled, or has no schedule — derived from the exact `payout due`/`overdue` rules, so the book answers "who needs paying when" without cross-checking two more commands. `payout suggest` lists only actionable rows and `freelancer show` covers one freelancer at a time; this covers everyone. Read-only: nothing is recorded or transferred. An empty roster prints `no freelancers on the roster`; `--freelancer ID` restricts to one freelancer, `--as-of DATE` projects the timing as of that day, and an unknown id or invalid date is a clean error. `--csv PATH` (v0.33.0) exports the same view as a spreadsheet: one row per freelancer per currency plus one TOTALS row per currency, with the same money columns (billed, collected, outstanding, paid out, still owed, suggested) and the same timing in trailing `payout_status` / `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule; freelancers with no billable invoices get a row with an empty currency and empty timing cells, and a mixed settled / no-schedule currency carries empty timing on its TOTALS row. `-` prints the CSV to stdout instead of the text summary; a file path writes the file and still prints the text summary. CSV exports neutralize spreadsheet formula injection (see `report`).

## `project`

```bash
invoiceguard project create --client "Acme Corp" --title "Website redesign" \
  --amount 2000 --currency USD --deposit-pct 50 \
  --late-fee-pct 1.5 --late-fee-grace-days 15 [--ack]
invoiceguard project list [--csv PATH]   # CSV in v0.43.0
invoiceguard project ack 1
invoiceguard project sign-request 1   # one-time e-signature link
invoiceguard project sign-status 1    # pending / signed + signer + hash
```

- `create` requires an existing client (matched by exact `--client` name) and `--title` and `--amount` (in currency units, e.g. `2000`).
- Defaults: `--currency USD`, `--deposit-pct 50`, `--late-fee-pct 1.5`, `--late-fee-grace-days 15`.
- Validation: `--deposit-pct` and `--late-fee-pct` must be between 0 and 100; `--late-fee-grace-days` must be 0 or more. Out-of-range values are refused before anything is written (the percentages also land in the generated contract text).
- Prints the generated contract (with the late-fee clause) as a preview.
- `--ack` records the contract as acknowledged by the client at creation time; without it, the contract shows `no-ack` until you run `project ack ID` after the client accepts the deposit link.
- `list` shows `#id  title  client  amount  [ack|no-ack]`. `--csv PATH` (v0.43.0) exports the same list as a spreadsheet: one row per project with the same columns the text lines print, incl. contract acknowledgment (`ack` / `no-ack`). `-` prints the CSV to stdout instead of the text list; a file path writes the file and still prints the text list. CSV exports neutralize spreadsheet formula injection (see `report`).
- `sign-request` creates a one-time, single-use signing link (`/sign/<token>`, served by the dashboard) for the client to type their name and draw a signature; the contract text is frozen at link-creation time and its SHA-256 is stored as tamper evidence. Re-running while a request is pending returns the same link (with its original frozen text). `sign-status` shows both tracks: the e-signature state *and* the deposit-link acknowledgment (`project ack` / `--ack`) — an acknowledged project with a signature still outstanding says so, instead of only reporting "awaiting signature" (0.8.4).

See [Contracts](contracts.html) for what the contract contains and the honest limits of the e-signature.

## `invoice`

```bash
invoiceguard invoice create --project 1 --kind deposit [--amount 1000] [--due-days 7]
invoiceguard invoice list [--freelancer 1] [--csv invoices.csv]
invoiceguard invoice assign 1 --freelancer 1   # or: --none to clear
invoiceguard invoice record-payment 1 --amount 250 [--note "check #1"] [--method bank]
invoiceguard invoice mark-paid 1
invoiceguard invoice void 1
invoiceguard invoice late-fees 1 [--as-of 2026-10-06] [--csv late-fees.csv]
invoiceguard invoice notify 1 [--channel sms|whatsapp] [--dry-run]
invoiceguard invoice report [--as-of 2026-10-08] [--freelancer 1] [--csv invoices.csv] [--payments-csv payments.csv]
```

- `create` requires `--project` (id) and `--kind`: one of `deposit`, `milestone`, `final`.
- Amount defaults by kind: `deposit` = `deposit_pct`% of the project total; `final` = the remainder after the deposit; `milestone` = the full project amount. `--amount` overrides in currency units.
- `--due-days` defaults to 7; `0` or negative means "due today".
- On success it creates a real Stripe payment link (test mode friendly), stores the URL, and sets status to `sent`. If the Stripe secret key is missing or still the placeholder, the command fails with a clear error — no invoice is left half-created.
- `list` shows `#id  kind  status  amount  project  [freelancer]  due-date`; `--freelancer ID` shows only that freelancer's invoices. Each line also carries payout timing (v0.45.0) for the invoice's attributed freelancer, taken from the same `agency summary` rows (derived from the exact `payout due` / `overdue` rules as of `--as-of`, default today): due, overdue (with the missed run date), upcoming, settled, or no schedule — per currency, matching the invoice's own currency. Unassigned invoices and freelancers with no billable invoices carry no timing phrase. `--csv PATH` (v0.42.0) exports the same list as a spreadsheet: one row per invoice, in the same id order the text lines print them, with the same columns the text lines print (invoice id, kind, status, amount, currency, project, freelancer, due date — freelancer empty when unassigned, due date empty when unset) plus the same timing in trailing `payout_status` / `payout_date` columns. `-` prints the CSV to stdout instead of the text view; a file path writes the file and still prints the text view with a `wrote invoice list CSV` note. An empty list exports a header-only CSV. An invalid `--as-of` is a clean error, not a traceback. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only.
- `assign` (v0.8.0, agency mode) attributes an invoice to a freelancer (`--freelancer ID`), or clears the attribution with `--none`. Pure bookkeeping: dunning, payments, and status are untouched.
- `record-payment` records a (partial) payment in the ledger. A payment that clears the outstanding balance marks the invoice `paid`; otherwise the invoice becomes `partially-paid` and keeps dunning against the remaining balance. Overpaying is rejected.
- `mark-paid` manually marks an invoice paid — since v0.2.0 it records the full outstanding balance in the ledger, and it errors on already-paid or void invoices. `void` voids an unpaid invoice; a **paid** invoice cannot be voided (0.8.4 — its ledger payments stand; refund through Stripe instead), and voiding an already-void invoice errors too.
- `late-fees` (v0.4.0) shows the accrued late fees for an invoice under contract §3: due date, grace window, monthly rate, months billed, accrued fees, and total due. One fee is billed per **full monthly period elapsed** since accrual started (0.8.4 — see the changelog for why started-calendar-month counting was wrong). `--as-of YYYY-MM-DD` computes as of a past date (default: today). `--csv PATH` (v0.44.0) exports the same accrual as a spreadsheet: one row with the same columns the text view prints (invoice id, client, project, currency, due date, rate, grace days, accrual start, as-of date, outstanding, months billed, accrued fees, total due). `-` prints the CSV to stdout instead of the text view; a file path writes the file and still prints the text view with a `wrote invoice late-fees CSV` note. CSV exports neutralize spreadsheet formula injection (see `report`). Read-only.
- `notify` (v0.5.0) sends an SMS/WhatsApp payment reminder for one invoice right now (same text as the automatic day-15 message). `--dry-run` prints the rendered message without sending — no Twilio credentials needed, but the client needs a phone number.
- `report` (v0.6.0) is a read-only receivables report: open invoices (sent / overdue / partially-paid with a balance) grouped into Current / 1-30 / 31-60 / 61-90 / 90+ day aging buckets, oldest debt first, with accrued late fees, per-client totals, and grand totals. `--as-of YYYY-MM-DD` pins the report date. `--csv PATH` exports one row per open invoice and `--payments-csv PATH` exports the full payment ledger for accounting; `-` as the path prints that CSV to stdout instead of the text report. `--freelancer ID` (v0.8.0) restricts the report to one freelancer's invoices; the text report also prints a "by freelancer" breakdown when more than one attribution group has open invoices. Each "by freelancer" line also carries payout timing (v0.26.0): due, overdue (with the missed run date), upcoming, settled, or no schedule — per currency, matching the row's own currency, taken from the same `agency summary` rows and projected with `--as-of`; the "unassigned" line carries no timing phrase. The invoice CSV export carries the same timing (v0.31.0): each row gains trailing `payout_status` and `payout_date` columns — the missed run date when overdue, the next payout date when due or upcoming, empty for settled / no schedule and for unassigned invoices. The payments CSV export carries the same timing (v0.32.0): each payment row gains the same two trailing columns, joined through the payment's invoice — its attribution and its currency, so a payment in EUR carries the freelancer's EUR timing — projected with `--as-of`, empty for unassigned invoices, and payments on paid invoices still export with timing. It never sends anything or changes invoice state. CSV exports (v0.8.1) neutralize spreadsheet formula injection: any exported cell starting with `=`, `+`, `-`, `@`, `|`, or `%` is prefixed with a single quote so it opens as plain text (OWASP CSV-injection guidance).

## `check-due`

```bash
invoiceguard check-due
```

Scans for overdue invoices (`sent`/`overdue` status, due date in the past) and sends the next dunning stage. Refuses to run until SMTP is configured. Meant for cron — see [Dunning engine](dunning.html).

## `dashboard`

```bash
invoiceguard dashboard [--port 8000] [--host 127.0.0.1]
```

Launches the localhost web UI (uvicorn serving the FastAPI app). Binds to `127.0.0.1` by default — keep it that way unless you know what you're doing. See [Dashboard](dashboard.html).

## Exit behavior

Errors print a one-line message (`Error: ...`) and exit non-zero. Destructive operations (`void`, `mark-paid`) act on explicit ids only — there is no bulk mode in v0.8.4.
