Installation

InvoiceGuard is local-first: everything runs on your machine against a SQLite database, driven by a single YAML config file. Install from PyPI:

pip (recommended)

terminal
pip install invoiceguard
invoiceguard init

invoiceguard init walks you through one-time setup: it creates the SQLite database and writes the single YAML config file with sane defaults.

Docker Compose

Prefer containers? A Compose file is included — it runs InvoiceGuard plus the local dashboard. See the README in the repo for the exact service definition.

terminal
docker compose up -d

Stripe setup

InvoiceGuard collects deposits through Stripe payment links. It is test-mode friendly — you can run the entire flow end to end without moving real money.

  1. In your Stripe dashboard, create a restricted API key (payment links + customers are enough).
  2. Paste the key into your YAML config (or the init wizard).
  3. Point a Stripe webhook at your instance so deposit payments are recorded automatically.
  4. Stay in test mode until you've run a full project cycle, then switch the key to live.
Tip: run your first project entirely in test mode — create a project, pay the test deposit, create a test invoice, and let check-due fire the day-1 nudge at yourself.

SMTP setup

InvoiceGuard has no built-in mail service. Bring your own SMTP — Gmail, your host, Amazon SES, anything that speaks SMTP. Add it to the single YAML config:

config.yaml
smtp:
  host: smtp.example.com
  port: 587
  username: you@example.com
  # password via the INVOICEGUARD_SMTP_PASSWORD environment variable —
  # never store it in the config file

All escalation emails are sent from your address, so replies land in your inbox — not a third party's.

Contract & dunning configuration

Each project links a Stripe deposit payment link to a contract that carries a late-fee clause. Before the client can pay the deposit, they acknowledge the contract with a checkbox.

The escalation schedule

When invoiceguard check-due finds an invoice past its due date, it sends the next stage automatically:

  • Day 1 — polite nudge. Friendly tone, invoice attached, payment link included.
  • Day 7 — firm reminder. Direct tone, due date and days-overdue stated.
  • Day 15 — formal notice. Quotes the signed late-fee clause and states that fees now apply.

All three email templates live in the YAML config — edit the subject lines, the body copy, and the late-fee terms to match how you talk to clients.

Not legal advice. The late-fee clause is a template starting point. For invoices that matter, have a local professional review your contract terms.

FAQ

Do I have to stop using FreshBooks / Wave / my invoicing tool?
No. InvoiceGuard is a sidekick, not a switch — it works alongside your existing tools through Stripe. Keep invoicing wherever you invoice; InvoiceGuard adds the deposit link, the late-fee contract, and the automatic escalation.
Is the client's checkbox acknowledgment legally binding?
In v1 it's an acknowledgment checkbox, not a full e-signature — it records that the client saw and accepted the late-fee clause before paying the deposit. Real e-signature support is on the roadmap. This isn't legal advice; for large invoices, get your terms reviewed professionally.
Where does my data live?
On your machine, in a local SQLite database. There is no cloud account in v1 and nothing is sent anywhere except Stripe (for payments) and your own SMTP server (for emails).
What does it cost?
v1 is self-hosted — free to run on your own machine. Managed hosting is coming later, planned at a flat $15–29/mo. No dates announced yet.
Does it work in Stripe test mode?
Yes — it's designed to be set up and tested fully in test mode before you switch a key to live.

Limits of v1

Honest boundaries, so there are no surprises:

  • Acknowledgment checkbox, not e-signature. The client confirms the late-fee clause with a checkbox. Real e-signature is roadmap.
  • No built-in mail service. You bring your own SMTP credentials.
  • Single machine. SQLite, one YAML config — no multi-user or team features in v1.
  • Email-only dunning. Escalation goes out by email; SMS/WhatsApp reminders are not in v1.
  • Managed hosting: coming soon. No waitlist, no launch date yet.

Roadmap

What's planned next — no dates, shipped when ready:

  • Real e-signature for the late-fee contract (replacing the v1 acknowledgment checkbox).
  • Managed hosting — flat $15–29/mo planned, so you don't have to run anything yourself.
  • More dunning channels beyond email.
  • Milestone-based deposit links for longer projects.
